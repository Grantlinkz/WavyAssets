## Non-Negotiable Invariants

1. **Mandatory Git Branch Isolation (`frontend-admin-panel`)**:
   All commits, branch operations, and UI additions for `Frontend/admin-panel` must strictly occur on the **`frontend-admin-panel`** git branch. Never commit frontend admin changes directly to `main` or `backend-admin-panel`.
2. **Zero Static Values & Zero Mock Fallbacks (Strict Non-Negotiable)**:
   Because the backend (`Backend/admin-panel`) is implemented simultaneously using Antigravity IDE Duplicate Workspaces, **no mock data, hardcoded fallback arrays, or static placeholder records are permitted in `Frontend/admin-panel`**. All tables, forms, and telemetry must query live endpoints at `http://localhost:4002/api/v1` and listen for live events on `http://localhost:4002/ws/admin`. If an endpoint is pending hydration, the component must render a rigidly dimensioned skeleton loader.
3. **Sub-50ms Interaction SLA**:
   Local filtering, search inputs, tab switching, and state mutations must execute in $<50$ms. Local state search is memoized via `useMemo` and Zustand shallow pickers.
4. **Zero Cumulative Layout Shift (CLS = 0.00)**:
   All table views, inspection drawers, and metric grids incorporate rigid, pre-dimensioned skeleton loaders (`min-height: 540px`, exact column widths) using the `.wavy-skeleton` shimmer animation (`linear-gradient(90deg, #141B29 25%, #1D2232 50%, #141B29 75%)`). No layout shifts during async data hydration.
5. **Official Institutional Branding**:
   The admin console must incorporate the official `BrandLogo` (Vault Squircle, Gold `#D4AF37` / Emerald `#00C288` dual sinusoidal wave, apex spark, and pulsing `#00C288` `SECURED` badge) from `Frontend/landing-page/src/components/common/BrandLogo.tsx` and official `favicon.svg`.
6. **Obsidian Dark & Sovereign Institutional Aesthetic**:
   High-contrast, high-density financial terminal aesthetic strictly abiding by the 4px micro-chamfer token system (`--radius: 0.25rem` / `rounded-[4px]`) and `tools/UI/institutional_vault_capital/DESIGN.md`. Consumer pill buttons $>8\text{px}$ are strictly forbidden.
7. **Tabular Lining Figures**:
   All monetary amounts, timestamps, wallet addresses, and hashes must use strict monospace tabular figures (`font-mono tabular-nums` with OpenType `'tnum' on, 'zero' on, 'cv01' on`).
8. **Role-Based View Masking**:
   Interfaces must strictly reflect the authenticated operator's role (`SUPER_ADMIN`, `TREASURY_OFFICER`, `COMPLIANCE_OFFICER`, `CONCIERGE`, `DESK_LEAD`), hiding unauthorized command buttons.
9. **Real-Time Cross-Deck Synchronization**:
   Live Socket.IO events (e.g. VIP card lock/unlock, KYC tier approval, deposit rail IBAN changes, emergency freeze) must immediately update the UI and broadcast state to client viewports.

## Human-in-the-Loop Rules

- Always propose an implementation plan or prompt in `prompts/<sprint>-<unit>.md` and obtain user approval before writing code.
- Stop and prompt for human review whenever encountering ambiguity, visual design trade-offs, or complex state synchronizations.
- Provide clear verification steps, typecheck proof, and automated test results after completing any unit of work.

## Git Commit Standards

- **Branch Enforcement**: Verify active branch is `frontend-admin-panel` before every commit (`git rev-parse --abbrev-ref HEAD`).
- **Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features (e.g. `feat: implement split-screen KYC document inspection deck`)
  - `fix:` for bug fixes (e.g. `fix: resolve tabular alignment jump on treasury deposits table`)
  - `refactor:` for code refactoring (e.g. `refactor: extract live deposit rail synchronization hook`)
  - `docs:` for documentation updates (e.g. `docs: update progress-tracker and component contracts`)
  - `tests:` for tests addition and modification (e.g. `tests: add Vitest suite for dual-sign-off modal`)
  - `chore:` for maintenance tasks and environment setup (e.g. `chore: configure Tailwind CSS v4 micro-chamfer tokens`)

## Pre-Commit Rules

Before committing code, submitting changes, or marking a task complete:

1. Confirm current branch is `frontend-admin-panel` (`git rev-parse --abbrev-ref HEAD`).
2. Run and pass all static analysis checks (`npm run lint`, `npx tsc --noEmit`).
3. Ensure the project builds successfully without errors or warnings (`npm run build`).
4. Ensure Unit and Component tests are passing in `Tests/UnitTest/` and `Tests/IntegrationTest/`.
5. Verify zero hardcoded mock/fallback data exists in active component trees.
6. Verify official `BrandLogo` and `favicon.svg` branding integrity.
7. Verify zero CLS (`min-height: 540px`), `.wavy-skeleton` shimmer, and tabular numeric formatting.
8. Update docs and `.ai/progress-tracker.md` after every phase or step.
