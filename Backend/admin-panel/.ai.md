## Non-Negotiable Invariants

1. **Mandatory Git Branch Isolation (`backend-admin-panel`)**:
   All commits, branch operations, and feature additions for `Backend/admin-panel` must strictly occur on the **`backend-admin-panel`** git branch. Never commit backend admin changes directly to `main` or `frontend-admin-panel`.
2. **FINMA AMLA Article 14 Dual Sign-Off Rule**:
   Outbound withdrawals exceeding **$100,000 USD** cannot be settled via automated straight-through processing. Any withdrawal $> \$100,000$ strictly mandates dual authorized officer sign-offs recorded in `TreasurySignOff` before balance release.
3. **Double-Entry Financial Ledger Conservation**:
   All direct capital funding, manual adjustments, wire clearances, and withdrawal settlements must execute as atomic database transactions (`prisma.$transaction`) across `LedgerTransaction` and `LedgerEntry` ensuring $\sum \text{Debits} + \sum \text{Credits} = 0$.
4. **Emergency Platform Freeze & Kill-Switch**:
   The emergency freeze mechanism must instantly halt all mutating transactions (deposits, withdrawals, trading, card spending) across all services when triggered, requiring Super Admin dual-key confirmation and broadcasting `platform:emergency_freeze` via WebSockets.
5. **PCI-DSS Level 1 & Zero Plaintext Secrets**:
   Plaintext card PINs, CVVs, user passphrases, and bearer tokens are strictly forbidden from database storage and runtime logging. Card PINs are encrypted via AES-256-GCM; CVVs are ephemeral; passphrases use Argon2id.
6. **Production Sandbox Guard**:
   In `NODE_ENV=production`, mock OTP codes and console email fallbacks are strictly rejected with HTTP `403 Forbidden` and flagged as an intrusion anomaly.
7. **Zero PII Logging & Standardized Envelope**:
   All emitted logs must automatically redact passwords, tokens, full names, email addresses, and account numbers. All endpoints must return the standardized response envelope:
   `{ success: boolean, data?: T, error?: string, timestamp: string }`.
8. **Strict Input Validation**:
   Every incoming request must be validated using `class-validator` through the global `ValidationPipe` with `whitelist: true` and `forbidNonWhitelisted: true`.
9. **Low Latency SLA**:
   Administrative queue queries, table filtering, and state transitions must satisfy an operational latency benchmark of `< 50ms`.

## Git Commit Standards

- **Branch Enforcement**: Verify active branch is `backend-admin-panel` before every commit.
- **Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features (e.g. `feat: implement FINMA Article 14 dual sign-off engine`)
  - `fix:` for bug fixes (e.g. `fix: resolve double-entry debit credit balance rounding`)
  - `refactor:` for code refactoring (e.g. `refactor: extract AES-256-GCM decryption pipeline for lead telemetry`)
  - `docs:` for documentation updates (e.g. `docs: update progress-tracker and API contracts`)
  - `tests:` for tests addition and modification (e.g. `tests: add Vitest suite for dual sign-off threshold`)
  - `chore:` for maintenance tasks and environment setup (e.g. `chore: configure prisma schema and admin roles`)

## Pre-Commit Rules

Before committing code, submitting changes, or marking a task complete:

1. Confirm current branch is `backend-admin-panel` (`git rev-parse --abbrev-ref HEAD`).
2. Run and pass all static analysis checks (`npm run lint`, `npx tsc --noEmit`).
3. Ensure the project builds successfully without errors or warnings.
4. Ensure Unit and Integration tests are updated and passing in `Tests/UnitTest/<test-name>` and `Tests/IntegrationTest/<test-name>`.
5. **Error Handling & Logging**: Verify that all new pathways return standardized `{ success, data, error, timestamp }` envelopes, sanitize errors, and redact PII from logs.
6. Update docs, OpenAPI annotations at `/api/docs`, and `.ai/progress-tracker.md` after every phase or step.
