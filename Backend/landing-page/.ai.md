## Non-Negotiable Invariants

1. **Production Sandbox Guard (Strict Non-Negotiable)**:
   In `NODE_ENV=production`, `DEV_STATIC_OTP` and `EMAIL_PROVIDER=console` are strictly forbidden. Any attempt to use development mock codes or console fallbacks in production must be immediately rejected with HTTP `403 Forbidden` and flagged as an intrusion anomaly.
2. **Documentation Updates (Docs)**:
   Docs must be updated after every phase or step — keep context files, OpenAPI/Swagger specifications at `/api/docs`, progress tracking, and code in strict lockstep before declaring work complete.
3. **Global Error Handling & Error Handling When Required**:
   All endpoints must return the standardized response envelope:
   `{ success: boolean, data?: T, error?: string, timestamp: string }`.
   Client responses must never leak stack traces, internal errors, or database infrastructure details. All uncaught exceptions must be intercepted by `AllExceptionsFilter`.
4. **Secure Logging (Zero PII)**:
   All emitted logs must automatically redact passwords, OTP codes, authorization tokens, secrets, full names, and sensitive email prefixes.
5. **Comprehensive Testing**:
   Unit and Integration tests must be updated after every phase or step, arranged strictly in dedicated directories (`Tests/UnitTest/<test-name>` and `Tests/IntegrationTest/<test-name>`).
6. **Strict Input Validation**:
   Every incoming request must be validated using `class-validator` and `class-transformer` through the global `ValidationPipe` with `whitelist: true` and `forbidNonWhitelisted: true`.
7. **Cryptographic Hygiene**:
   Passwords and OTPs must be hashed with Argon2id memory-hard parameters; sensitive lead contact fields must be encrypted at rest with AES-256-GCM; refresh tokens must be delivered via `HttpOnly`, `Secure`, `SameSite=Strict` cookies.
8. **Low Latency SLA**:
   API responses must satisfy an operational latency benchmark of `< 50ms`.

## Git Commit Standards

- **Git Commit Frequency**: Commit code as you build. Every working session or phase must contain **at least two git commits**.
- **Conventional Commit Patterns**: All git commit messages must strictly adhere to the following prefixes:
  - `feat:` for new features (e.g. `feat: implement Argon2id password hashing and 2-step OTP challenge`)
  - `fix:` for bug fixes (e.g. `fix: resolve rate limiter sliding window expiration bug`)
  - `refactor:` for code refactoring (e.g. `refactor: extract AES-256-GCM cipher into reusable encryption service`)
  - `docs:` for documentation updates (e.g. `docs: update progress-tracker and API contracts`)
  - `tests:` for tests addition and modification (e.g. `tests: add Vitest suite for brute-force auth lockout`)
  - `chore:` for maintenance tasks and environment setup (e.g. `chore: configure prisma schema and throttler module`)

## Pre-Commit Rules

Before committing code, submitting changes, or marking a task complete:

1. Run and pass all static analysis checks (`npm run lint`, `npx tsc --noEmit`).
2. Ensure the project builds successfully without errors or warnings.
3. Ensure Unit and Integration tests are updated and passing in `Tests/UnitTest/<test-name>` and `Tests/IntegrationTest/<test-name>`.
4. **Error Handling & Logging**: Verify that all new pathways return standardized `{ success, data, error, timestamp }` envelopes, sanitize errors, and redact PII from logs.
5. **Production Sandbox Guard**: Verify that `ProductionSandboxGuard` rejects sandbox codes when in production mode.
6. Update docs, OpenAPI annotations at `/api/docs`, and `.ai/progress-tracker.md` after every phase or step.
